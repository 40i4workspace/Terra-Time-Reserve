# T.E.R.R.A. Time Reserve — closed-vault backend

FastAPI + Supabase/PostgreSQL foundation for an internal ownership registry. This is **not** a blockchain bridge or wallet service: there is no external-address field or withdrawal API. Every partition remains at `TERRA-MASTER-VAULT`; a transfer atomically changes only the owner record under a PostgreSQL row lock.

## Security model

- `ADMIN_ROOT` has a 12-digit HMAC-SHA-512, time-derived password that rotates every 15 minutes. Only its seed is held in a secret manager (`ADMIN_PASSWORD_SEED`); no admin password is stored in Postgres or in this repository. The immediately preceding interval is accepted only to handle a request at the interval boundary.
- Admin sessions are short-lived (10 minute HS512 JWTs), bearer-authenticated, and carry the sole `ADMIN_ROOT` role.
- End-user authentication uses a verified Supabase access JWT (`sub` is `auth.users.id`). The backend connects through private Postgres, not a browser client.
- Biometric **templates are never received or stored**. Identity registration accepts exactly a 32-byte opaque hash generated by an approved biometric/identity provider.
- Ownership certificates are signed with Ed25519, then sealed to an X25519 recipient public key with ephemeral ECDH, HKDF-SHA256, and AES-256-GCM. The vault registry, not the certificate, is authoritative. Revocation makes a stolen certificate unusable immediately.
- Decimal quantities are exact `numeric(150,72)` / Python `Decimal` values. Floats and values with >72 fractional digits are rejected.

## Setup

1. Create the Supabase project and run `supabase/migrations/20260726000000_terra_vault.sql` via the Supabase CLI/migration pipeline. It requires `auth.users`, which Supabase provides.
2. Generate production secrets (write output straight to your secret manager):
   ```sh
   ./scripts_generate_admin_secrets.py
   ```
3. Provide these environment variables. Never commit a `.env` file:
   ```sh
   export SUPABASE_DATABASE_URL='postgresql://private-api-role:...@db.example:5432/postgres?sslmode=require'
   export SUPABASE_URL='https://YOUR_PROJECT.supabase.co'
   export SUPABASE_JWT_SECRET='Supabase JWT signing secret'
   export ADMIN_PASSWORD_SEED='generated secret'
   export ADMIN_JWT_SECRET='generated secret'
   export CERTIFICATE_SIGNING_KEY='base64 32-byte Ed25519 seed'
   ```
   Use a non-owner database role; it must not have direct `INSERT`, `UPDATE`, or `DELETE` grants on `terra_partitions`. Restrict it to the three vault functions plus the controlled certificate/identity writes required by this API. Keep the migration owner separate.
4. Install and run:
   ```sh
   python -m venv .venv && . .venv/bin/activate
   pip install -r requirements.txt
   uvicorn app.main:app --host 127.0.0.1 --port 8000
   pytest -q
   ```

## Units and visibility

| Unit | RBH/hour value | Standard-user listing |
|---|---:|---|
| `$HRR` | 1 | visible |
| `$TRR` | 1 | visible |
| `$DAY` | 24 | hidden |
| `$MON` | 720 | hidden |

All denominations are present in `terra_denominations`; admin issuance can create any of them. `/me/partitions` intentionally omits `$DAY` and `$MON`; `GET /admin/denominations` and `GET /admin/partitions` expose the complete inventory to an authenticated `ADMIN_ROOT` session.

## API flow

1. Create a Supabase user, then `POST /admin/identities` using the rotating root login/session.
2. Admin calls `POST /admin/partitions` with an internal user UUID, exact decimal quantity, denomination, and recipient X25519 PEM. It receives a serial such as `TRR-2026-000001` and encrypted certificate.
3. A user calls `POST /me/transfers` with owned partition UUIDs and an already registered destination user. PostgreSQL locks each partition, validates ownership, changes only the internal registry, audits it, supersedes stale source certificates, and seals a newly signed certificate to the recipient.
4. `POST /me/certificates/{id}/revoke` immediately blacklists an active certificate. It never moves or destroys vault-held tokens.

The API deliberately has no wallet-address, chain, bridge, export, or withdrawal endpoint.
